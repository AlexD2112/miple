# fixtures/large2: batch 2 of synthetic test data for Miple (robustness and coverage)

Everything here is **synthetic** and generated by the seeded scripts in `_gen/`. Every record has `synthetic: true`, and every item record also has `observed: false`.

**Where labels come from.** Labels are derived only from these sources:
- `../shelf_life.json`: categories, `default_storage`, and day counts. No shelf-life number in this folder is invented.
- `../allergens.json`: allergen labels, computed with the documented batch-1 matcher in `../large/_gen/allergen_matcher.py` (rules R1–R9 in `../large/README.md`).
- Batch-1 building blocks, imported **read-only** from `../large/_gen`: catalog, store abbreviations, tax/deposit/bag rules, and price logic. Batch-1 files are never modified, and no bytecode is written there.

**Seed and reproducibility.**
- Batch-1 seed: `SEED = 20261017`.
- Batch-2 base seed: `SEED2 = SEED + 2,000,000` (`_gen/rcore.py`). Each set adds its own offset: adversarial +100,000, normalization +200,000, e2e +300,000, dates +400,000/+450,000.
- Output is byte-for-byte reproducible, independent of `PYTHONHASHSEED`.

| Set | Files | Count |
|---|---|---|
| Adversarial receipts | `adversarial/text/NNN/A#####_<category>.txt`, clean `adversarial/source/…`, `adversarial/expected.jsonl` | 2,260 (14 categories) |
| Normalization pairs | `normalization/pairs_00{0,1,2}.jsonl`, `normalization/items.jsonl` | 30,000 pairs (10,183 hard-negative rows), 335 items |
| End-to-end cases | `e2e/receipts/NNN/E#####_<store>.txt`, `e2e/cases.jsonl` | 2,000 receipts, 20,031 expected pantry entries, 6,000 profile evaluations |
| Date/time formats | `dates/header_cases.jsonl`, `dates/receipts/*.txt`, `dates/receipts_expected.jsonl` | 6,000 header cases (17 formats), 300 full receipts |

About 46 MB in total. The largest file is about 14.5 MB.

## Regenerate and validate
```
cd fixtures/large2/_gen
python3 gen_adversarial.py
python3 gen_normalize.py --n 30000
python3 gen_e2e.py --n 2000
python3 gen_dates.py --n 6000 --receipts 300
cd .. && python3 validate.py
```
Requirements: Python 3.10+ standard library, plus `zoneinfo` with system tzdata for the PDT/PST check. The scripts read `../shelf_life.json`, `../allergens.json`, `../receipt_lines.json` and `../large/_gen/*.py`.

## 1. Adversarial / robustness receipts (`adversarial/`)
Each case has a clean source receipt in batch-1 layout and a transformed text. `expected.jsonl` records the following for each case:
- `category`.
- `receipts[]`: ground truth for every receipt in the text. Each item carries `raw_text`, `normalized_name`, `price`, `flag`, `taxable`, `category`, `line_type`, and `source_line`, which is its line in the source file. Each receipt also has `subtotal`, `tax`, `total`, `printed{}`, `tenders`, and `flag_legend`.
- Flags: `truncated`, `duplicated`, `concatenated`, `store_error`, `ignored_lines`, `line_ops`.

| category | n | what it tests / label |
|---|---|---|
| columns_misaligned | 200 | Per-line single-space gaps, leading indents (item lines that look like detail lines), tabs, jitter, trailing whitespace. `line_ops` lists each line; items are unchanged. |
| column_split | 150 | OCR emitted the description column, then the amount column. Block ranges are in `line_ops`. |
| upside_down | 100 | Line order is reversed (a scan read bottom to top). |
| double_scan | 250 | An overlapping block of 3–8 lines is repeated, or the whole receipt is scanned twice. `duplicated=true`; `line_ops` gives `start`/`end`/`copy_start`; expected items count each line once. |
| legit_repeat | 100 | Hard negative for double_scan: the same item was really bought twice in a row. `duplicated=false`, and both lines are expected. |
| cut_off | 250 | The text is a prefix of the source. `truncated=true`. Expected items are only those whose amount line was printed. Totals, tenders and printed values are `null`, and `complete=false`. About 15% are cut inside the header (0 items). |
| concatenated | 200 | Two receipts joined, with no separator, blank line(s), or a dashed rule. `receipts` has 2 entries; `second_starts_at` is given. |
| promo_noise | 250 | Survey codes, rewards and fuel-point balances, "WIN A 500.00 GIFT CARD", auth codes, masked card numbers, "BALANCE DUE 0.00", next-visit coupons, and indented "YOU SAVED x.xx" / "REG PRICE x.xx" lines inside the item block. All are listed in `ignored_lines`; none are items. |
| flag_variants | 200 | Alternate tax-flag schemes: T/F, T/N, TX/blank, A/E, N/F, B/blank, T/S. Each item has `flag`, and `flag_legend` says which flag means taxable. |
| tax_exempt | 60 | A "TAX EXEMPT ID ******1234" receipt: `tax_exempt=true`, `tax=0`, even though `taxable_base > 0`. |
| store_error | 200 | The printed values disagree with the line items. Kinds: `total_off` (±1¢ to $1), `tax_old_rate` (WA tax printed at 10.35% instead of 10.55%), `subtotal_missing_item`. `store_error` records `mismatched_fields`, `computed`, `printed`, and `kind`; tenders match the printed total. |
| very_long | 60 | 150–260 items (Costco, Safeway, Fred Meyer). |
| all_non_food | 120 | Only non_food items; everything is taxable in WA/CA. |
| all_return | 120 | Only `RETURN …` lines: negative subtotal and total, with a negative tender (refund). |

## 2. Item normalization pairs (`normalization/`)
- **What a pair is:** `raw_text` (store-specific) → `normalized_name` + `category` + `app_category_key`.
- **Fields:** `variant_ops`, `label_source`, `hard_negative`, `confusable_with`, and `ocr_noise`.
- **Variant ops:** store brand prefixes, the batch-1 word map plus an extended alternative-abbreviation table, vowel dropping, 4-letter clipping, size suffixes, TJ-style mixed case, Costco item numbers, printer-width truncation, and OCR character swaps.
- **Truncation rule:** truncation only clips inside the **last** token and keeps at least 3 of its characters, so an item is never cut down to the point where it becomes a different item.

**Label provenance (`label_source`):**
- `shelf_life.examples`: the category is the example's category.
- `receipt_lines.json`: the curated line category.
- `non_food_list` or `batch1_catalog_beverages`: from the batch-1 lists.
- `hard_negative:analog=<example>`: the item inherits the category of a named `shelf_life.json` example. Examples:
  - "chicken broth" → analog "chicken broth carton" → canned goods (confusable: raw poultry).
  - "berry blast cereal" → analog "cereal" → **snacks**. The curated `shelf_life.json` maps cereal to snacks, not dry goods.
  - "orange juice" (beverages) vs "navel oranges" (fresh fruit).
  - "peanut butter" (opened condiments) vs "pbr 12pk cans" (beverages; analog "cola 12pk").
  - "turkey breast" (raw poultry) vs "sliced turkey breast" (deli meat).
  - "ground coffee" vs "ground beef".
  - "butter lettuce" and "butternut squash" vs butter.
  - "ice cream" vs "cream cheese".
  - Egg noodles and eggplant vs eggs.

  There are 60 hard-negative items in all; see `HARD` in `_gen/gen_normalize.py`.

**Collision guard:** any raw text that would map to two different (name, category) labels is moved to `ambiguous.jsonl` with every candidate listed. There were none in this run, so that file is not written.

## 3. End-to-end pipeline cases (`e2e/`)
**Input:** the receipt `.txt` plus `input.purchase_date`, which equals the printed receipt date. About 15% of cases use edge dates: 2028-02-28/29, Dec 30/31, Jan 31, 2027-02-28.

`expected` contains:
- `receipt`: parsed ground truth.
- `pantry[]`: one entry per food sale line. Rules:
  - A `RETURN` line removes the most recent matching earlier entry.
  - non_food, discount, fee and deposit lines are excluded and listed in `excluded_lines` with the reason.
  - Storage is the category's `default_storage`, and `shelf_life_days` comes from `shelf_life.json`.
  - `estimated_expiry` = `purchase_date + days`, or **null** when the day count is null (629 entries).
- Allergen fields on each pantry entry:
  - `allergen_keys` and `may_contain_keys` are app keys computed from `normalized_name` with the batch-1 matcher.
  - The app's `gluten` is treated as wheat, because `allergens.json` has no separate barley or rye list.
- `profiles[3]`: for each allergy set, `flagged_pantry_indexes` (contains) and `caution_pantry_indexes` (may-contain only).

## 4. Date/time format edge cases (`dates/`)
`header_cases.jsonl` holds a store-style header snippet plus `expected`:
- `date`, `time` (24-hour HH:MM), `seconds`.
- `two_digit_year`, `clock` (12h/24h), `timezone`/`tz_abbrev`.
- `after_midnight`, `ambiguous_local_time`, `business_date`.

**Formats (17):**
- `10/17/26 21:41`, `10/17/2026 21:41`, `10/17/26 09:41 PM`, `10/17/2026 09:41:05 PM`, `10-17-2026 9:41PM`, `10-17-26 21:41:05`
- `OCT 17 2026 09:41PM`, `2026-10-17 21:41:05`, `17-OCT-26 21:41`, `SAT OCT 17 2026 9:41 PM`, `10/7/26 9:05 PM` (unpadded), `10.17.26 21:41`
- `Oct 17, 2026 9:41 pm`, `9:41 PM 10/17/26` (time first), `Saturday, October 17, 2026 9:41 PM`, `10/17/2026 21:41 PDT`
- A date-only line followed by `TIME: 21:41`.

**Edge cases:**
- Times after midnight (00:00–02:59).
- 12:xx AM/PM (noon vs midnight).
- Leap days in 2024 and 2028.
- Year boundaries, including 2029→2030.
- DST fall-back hours on 2026-11-01 and 2027-11-07 (`ambiguous_local_time`).
- Day ≤ 12 cases such as 03/04 (read as US month-first).
- After-midnight receipts that carry a separate `BUSINESS DATE` for the previous day.

**Conventions:**
- `expected.date` is the printed transaction date; `business_date` is reported separately.
- Two-digit years use the POSIX pivot: 00–69 → 20xx.
- Snippets include distracting register and transaction numbers, and TJ's "OPEN 8:00AM TO 9:00PM" header times.
- Assigning formats to stores is synthetic: these are plausible styles, not ones observed on real receipts.

`receipts_expected.jsonl` holds 300 full receipts whose footer date block uses these formats.

## Tax, deposit and bag rules
These are the same as batch 1; see `../large/README.md`:
- WA Seattle: 10.55%; grocery food exempt; bag fee taxable.
- OR: no sales tax; 10¢ deposit; 5¢ bag (an assumption).
- CA San Francisco: 8.625%; CRV; 25¢ bag, not taxable.

## Validation (`validate.py`)
**General:**
- Every .json/.jsonl file parses.
- Every file is under 50 MB, and the total is under 150 MB.

**Adversarial:**
- Each source receipt is re-parsed with a parser that is independent of the generator: line items, flags, and line numbers.
- Recomputed subtotal, taxable base and tax (zero when tax-exempt) must match.
- Printed values must match, and `store_error.mismatched_fields` must be exactly the fields that differ.
- Tenders minus change must equal the printed total.
- Transform invariants per category: a cut is a prefix; removing a duplicate gives back the source; a reversed text reverses back; a column split rebuilds; concatenation is A + separator + B; removing inline promos gives back the source; misaligned lines differ from the source only in whitespace.

**Normalization:**
- Provenance checks: category matches the shelf_life example or analog, and matches the item table.
- No raw text has two labels, there are no duplicates, and all 7 stores appear.

**E2E:**
- Text re-parsed.
- Pantry membership, storage, days and expiry recomputed from `shelf_life.json`.
- Allergen keys recomputed with the matcher, and profile flags checked.

**Dates:**
- A general date/time parser re-reads every snippet and full receipt.
- PDT/PST is checked against tzdata.
